## Умова

Розробити консольний застосунок для розбору, валідації, фільтрації, агрегації та форматування рецептів. Класи не застосовуються: типи даних описані через Dart records та typedef. Вхідні дані задано константним списком CSV-подібних рядків, у тому числі з навмисними помилками.

## Структура

- `bin/main.dart` — точка входу, завантаження прикладів, обробка помилок, виведення результатів;
- `lib/lab1.dart` — записи `Recipe`, `Ingredient`, `ParseResult`, перевірки, групування, сортування, звіт;
- `analysis_options.yaml` — стандартний набір статичних перевірок;
- `pubspec.yaml` — назва пакета, сумісна версія Dart SDK, залежності.

Таке розділення потрібне, щоб перевірки та обчислення не були прив’язані до `print` і щоб наступні лабораторні могли використати предметну область.

## Вибір типів даних

- `List<String>` зберігає вхідні рядки у визначеному порядку.
- Запис `Recipe` групує поля рецепта без застосування класу.
- `List<Ingredient>` зберігає довільну кількість інгредієнтів разом з кількістю та одиницею вимірювання.
- `Map<String, List<Recipe>>` групує рецепти за назвою кухні.
- `Set<String>` забезпечує перевірку належності до дозволених складностей та одиниць.
- `ParseResult` повертає результат і список пояснень у разі помилки, без аварійного завершення.
- `DateTime` та `Duration` використовуються для коректної арифметики дати внесення.

## Формат даних

`назва;кухня;час_у_хвилинах;складність;інгредієнт:кількістьодиниця|...;дата_YYYY-MM-DD`

Поле дати **додано до базової сутності** для виконання пункту про арифметику дат. `sourceLines` містить 20 прикладів: 15 коректних і 5 навмисно пошкоджених (відсутнє поле, нечисловий час, неправильна дата, інгредієнт, вихід за допустимий діапазон).

## Розбір та валідація

Використано `split`, `int.tryParse`, `double.tryParse`, `DateTime.tryParse`. Після `tryParse` дата додатково перевіряється канонічним записом `YYYY-MM-DD`, щоб не прийняти нормалізовану неіснуючу дату. Названі групи `RegExp` мають назви `name`, `quantity` і `unit`. Маскування кількості демонструє `replaceAllMapped`.

## Обробка колекцій і замикання

- `quickRecipes` — `where`: фільтр за часом;
- `recipeTitles` — `map`: перетворення до назв;
- `totalMinutes` — `map` та `fold`: обчислення суми;
- `cuisineAverages` — групування через `Map<String, List<Recipe>>` і середнє для кожної кухні;
- `sortByDuration` і `sortByTitle` — різні критерії сортування, іменований параметр `ascending`;
- `buildReport` — `StringBuffer`, параметри `topCount`, `ascending`, `separator`, `now`;
- `makeCounter` — замикання, що захоплює власну змінну `count`. Кожний виклик фабрики створює новий незалежний стан.

Явний цикл `for` залишено для розбору вхідних рядків (потрібні і рецепт, і список помилок) та групування (покрокове наповнення `Map` читається зрозуміліше за вкладену згортку).

## Залежності й альтернативи

- `lints` — dev-залежність для перевірки стилю. Альтернативою було ручне підтримання набору правил, але рекомендована конфігурація простіша для супроводу.
- Для CSV-подібного формату, регулярних виразів, колекцій та дат використовуються лише стандартні бібліотеки Dart. Розглядалися `csv`, `collection`, `intl`, але їх не додано: вхідний формат навчальний, усі операції доступні у `dart:core`, локалізоване форматування дат не потрібне.

Модифікатори `late`, тип `dynamic` та оператор null assertion `!` **не використовуються**, тому небезпечні припущення про наявність значень відсутні.

## Запуск

Потрібен Dart SDK 3.13 або новіший:

```powershell
cd lab1
dart pub get
dart format .
dart analyze
dart run bin/main.dart
```

Для збереження підтвердженого результату:

```powershell
dart analyze > analyze_result.txt 2>&1
dart run bin/main.dart > program_result.txt 2>&1
```

**Статус:** програму необхідно запустити локально; на момент підготовки коду фактичний результат `dart analyze` ще не отримано. Не слід підміняти його очікуваним повідомленням.
